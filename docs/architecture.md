# 架构与判定逻辑说明

## 1. 为什么是「规则 + 大模型 + 人工」三层

| 层 | 优势 | 局限 | 在本项目中的职责 |
|---|---|---|---|
| 规则 | 毫秒级、零成本、完全可解释 | 只能覆盖确定性表述，遇到语境就误判 | 初筛出**疑似命中**，不做定性 |
| 大模型 | 能读语境、能给理由、能引用法条 | 会漂移、会编、成本高 | 对候选**逐条裁决**，并补充语义问题 |
| 人工 | 终局责任 | 慢、标准不一 | 复核采纳/修改/驳回，形成留痕 |

关键约束：规则**不能直接出意见**，否则等于把误报固化成结论；大模型**不能无边界发挥**，否则等于没有标准。

## 2. 数据流

```
材料 → 解析层（块化） → 规则初筛（候选 C1..Cn）
      → 大模型裁决（confirm / reject / findings）
      → Reduce（去重、排序、上限合并）
      → 人工复核（状态机）
      → 报告 + 业务链路
```

### 2.1 块化

不同格式统一成 `{ location, text }`：`正文`、`docx内嵌图片第N张`、`PDF第N页`、`PDF第N页（扫描）`、`长图切块N`、`第N页-文本框`。

块化的意义不只是"塞得进上下文"，更重要的是**每条意见都能定位回原材料的具体位置**——审查人员必须能凭此找到原文。

### 2.2 裁决协议

```json
{
  "rule_verdicts": [
    { "candidate_id": "C1", "verdict": "reject", "reason": "豁免依据" }
  ],
  "findings": [
    { "original_text": "逐字引用", "dimension": "维度五 ...", "judgment_path": "...", "legal_basis": "..." }
  ]
}
```

- `reject` 必须写明豁免依据，不能只写"不构成违规"——否则拦截无法复核；
- `findings` 只写规则层没提示的问题，避免重复；
- 模型漏裁的候选保留但降级标注，不静默丢弃。

## 3. 误报治理的三个层次

1. **规则层守卫**：定量参数豁免（最高+数字/参数名词），从源头减少候选；
2. **模型层裁决**：语境判断，拥有否决权；
3. **输出层后置门**：带时间标记的客观数据强制降为低风险；片段级材料不判"风险提示缺失"高危；引用不可检索直接剔除。

三层各管一段，任何一层都不指望"完全正确"。

## 4. 状态机（人工复核）

```
待复核 --采纳--> 已采纳
      --修改--> 已修改采纳
      --驳回--> 已驳回
已处理 --撤回--> 待复核（记入链路，标记已撤回）
任意   --撤销--> 上一步（栈深 ≤10，可重做）
阶段   --回退--> 上一步（历史保留，人工操作标记"已回退"）
```

约束：撤回后的待复核不阻塞完结，但会在报告中单列「未纳入审查结论的意见」；完结需二次确认。

## 5. 成本与延迟

- 单材料调用次数 ≈ 内容块数（短文本 1 次，长图 3~5 次，扫描 PDF 每页 1 次）
- 单块输出上限 8 条，控制单次生成长度
- 判定类任务用低温 + 非推理模型：实测同一提示词下，推理模型 90s 仅产出思考过程（正文 0 字），换快模型 5s 出完整 JSON
